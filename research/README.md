# Мини-исследование оптимизации

Исследование текущих функций прибыли. **В тестах не включены пороги IRR и ROE.** Это сравнение алгоритмов, а не готовые рекомендации по сделкам.

Запуск из корня проекта: `python -m research.benchmark`. Нужны NumPy и SciPy; проверено с SciPy 1.17.0. Основной пакет калькулятора по-прежнему не требует этих зависимостей.

## Постановка

Максимизируется чистая прибыль после помесячного налога. Соблюдаются спрос, лимит, выпуск и неотрицательность. Конечные объёмы кратны 1 млн ₽. Проверены четыре исходные сделки и стресс-вариант «Город N» с купоном 8%.

Для ускорения поиска используется векторный эквивалент существующих функций. На допустимых случайных точках и на каждом конечном решении он сверяется с `calculate_allocation`; допустимое расхождение — 0,10 ₽. Все конечные решения повторно проверены на ограничения. Время подготовки приводится отдельно в JSON. Время алгоритмов включает проверку их конечного результата, но не импорт библиотек. Это одиночный локальный замер, не оценка времени будущего сервера.

## Методы

- **Piecewise MILP:** интервалы x3 между кратными месячному темпу продаж. На каждом интервале помесячная прибыль до налога — аффинная функция четырёх объёмов. Чистая прибыль равна `min(p, (1-tax)*p)`. Вводим переменную z для каждого месяца с ограничениями `z <= p` и `z <= (1-tax)*p`, максимизируем сумму z. Объёмы целые в миллионах рублей. На каждом интервале решаем MILP и выбираем лучший результат. Это точная постановка текущей задачи без порогов доходности, в пределах числовых допусков решателя. Все интервалы завершились успешно с нулевым сообщённым mip_gap.
- **Differential evolution:** 3 seed, целочисленные переменные, линейные ограничения, 200 поколений, popsize=12, tol=1e-8, без polish. Совпадение с эталоном не является сертификатом оптимальности.
- **SLSQP:** 10 стартов, непрерывные объёмы, округление вниз до миллиона, повторная проверка. Округление может ухудшать результат; здесь после него достигнут тот же максимум. Метод не гарантирует глобальный результат на произвольных изменённых условиях.
- **Случайный поиск:** 5000 равномерных проб в прямоугольнике границ; недопустимые отбрасываются. Слабый контрольный метод, не конкурентный оптимизатор.

## Наблюдения

| Метод | Время на сценарий | Отклонение прибыли от MILP |
| --- | --- | --- |
| Piecewise MILP | 0,07–0,16 с | эталон |
| Differential evolution, один seed | 0,94–2,17 с | практически 0% во всех 15 запусках |
| SLSQP, суммарно 10 стартов | 0,29–0,36 с | практически 0% во всех 5 сценариях |
| Случайные 5000 проб | 0,33–0,38 с | 1,01–7,69% на базовых сделках; 45,37% в стрессе |

Полные результаты и распределения: `results.json`. Сравнение пока небольшое; базовые условия дают сравнительно простые оптимумы. Не проверены все пользовательские параметры, сценарии спроса и сложные денежные потоки. Исследовательский скрипт ориентирован на текущий старт продаж со второго месяца, положительный лимит/темп и фиксированный шаг 1 млн; это не универсальный production-оптимизатор.

## Как добавлять доходность

При положительном капитале ROE >= r переписывается как `sum(net_profit) >= r * sum(monthly_capital) / 12`. На интервалах перепродажи капитал аффинен, поэтому ограничение совместимо с такой MILP-постановкой.

Для денежных потоков с первоначальным отрицательным вложением и последующими неотрицательными выплатами IRR >= порога эквивалентно NPV по ставке порога >= 0. Это может позволить обойти вызов поиска IRR внутри оптимизации. При нескольких сменах знака эквивалентность нельзя предполагать: требуется отдельная обработка неоднозначной IRR. Комиссионные решения без капитала также обрабатываются отдельно. Эта расширенная постановка здесь ещё не реализована и не измерена.

## ML-подходы

Optuna/TPE и байесовская оптимизация разумны для дорогого чёрного ящика: вероятностная модель выбирает следующие точки. Здесь расчёт дешёвый и его структура известна; обучения на данных не требуется. Optuna в окружении не установлена, эксперимент с TPE не проводился. Нейросети и обучение с подкреплением на этом этапе не рекомендуются: потребуют отдельной модели/обучения без очевидной пользы для четырёх переменных.

Рекомендация: развивать piecewise MILP как основной кандидат, differential evolution — как независимую численную проверку. Выбор окончательно подтвердить после добавления ROE/IRR и стресс-тестов изменяемых параметров.
